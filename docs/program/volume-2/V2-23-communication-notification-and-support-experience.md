## V2-23.1 Purpose

This section is normative.

This chapter defines the communication matrix across the affiliation lifecycle. It defines
communication behaviour, not final templates or marketing copy (REG-203 CAP-V2-042,
FR-V2-040).

## V2-23.2 Communication triggers

This section is normative.

The communication matrix covers at minimum:

- seasonal affiliation opened;
- representative invited or changed;
- action required;
- approaching due date;
- evidence accepted or rejected;
- application submitted;
- reviewer assigned;
- return for information;
- resubmission received;
- escalation;
- decision recorded;
- fee or reconciliation issue;
- approved awaiting activation;
- activation completed;
- activation failed;
- affiliation nearing expiry;
- support case opened or transferred.

## V2-23.3 Communication descriptor

This section is normative.

Each communication identifies:

- Trigger;
- Audience;
- Authority source;
- Purpose;
- Required content;
- Prohibited content;
- Channel hypothesis;
- Urgency;
- Acknowledgement requirement;
- Escalation behaviour;
- Language obligation;
- Accessibility obligation;
- Audit requirement.

The captured concept is recorded as a communication matrix entry (REG-203 DATA-V2-022,
UX-V2-021).

## V2-23.4 Authority and prohibited content

This section is normative.

Every communication names an authority source. Communications never assert governed
decisions the sender does not hold and never disclose restricted evidence or
minimum-necessary-exceeding personal information (REG-203 CTRL-V2-019). Communication does
not create or mutate governed lifecycle status (REG-203 RULE-V2-027).

## V2-23.5 Support experience

This section is normative.

Support intake, service context, permitted assistance, restricted evidence, handoff, and
recovery are defined so that support assists and hands off without changing governed
authority (V2-20.7, REG-203 RULE-V2-029, BR-V2-030, UX-V2-018). A support case can be
converted into a governed case where required, through the appropriate authority.

## V2-23.6 Delivery failure

This section is normative.

When notification delivery fails, the experience provides an alternate path to the
required action and records the failure with audit (REG-203 TEST-V2-039, CTRL-V2-020).
Communication failure is an experience concern and is distinct from governed state.

## V2-23.8 Authorization posture

This section is normative.

implementation, no final templates, and no channel procurement. All referenced
