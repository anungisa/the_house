## Purpose

This chapter defines documentary observability, incident-response, problem-management,
and reconciliation runbooks for the affiliation vertical. It defines obligations only
and authorizes no monitoring configuration, numerical operational target, or tooling.

## Signals and runbooks

Documentary procedures are defined for command failures and unknown outcomes,
application and database health, outbox backlog, consumer delay or duplication,
event-ordering issues, webhook and callback failures, provider availability,
evidence-storage issues, import and export failures, quarantine growth, reconciliation
mismatches, activation conflicts, migration-health signals, and privacy and security
incidents. Each signal in REG-1101 and each runbook in REG-1102 records its signal
source, required correlation context, sensitivity, minimum-necessary diagnostic
posture, condition or threshold dependency, alert destination, operational owner,
escalation authority, containment action class, recovery dependency, reconciliation
requirement, problem-management dependency, evidence required, and future gate.

## Controlling distinctions

> Telemetry emitted is not signal observed is not alert delivered.
>
> An alert delivered is not an incident declared is not an incident handled.
>
> Incident resolved is not underlying problem eliminated.
>
> Service restored is not business state reconciled.

Emitting telemetry is not observing a signal; delivering an alert is not declaring an
incident; declaring an incident is not handling it. A resolved incident does not
establish that the underlying problem is eliminated, and a restored service does not
establish that business state is reconciled.

## Boundary

This chapter defines documentary runbooks. No monitoring configuration or numerical
operational target is authorized, and no incident is handled.
