## Purpose

This chapter defines the distinct acceptance classes that must be satisfied before
a release can be authorized, and the authorities, independence, and dissent
treatment attached to each. It defines acceptance obligations; it accepts nothing
and authorizes no release.

## Acceptance classes

The following acceptance classes are defined and held distinct, and each is
recorded in register REG-1201 as an acceptance class:

```
Technical acceptance
Domain acceptance
Security and privacy acceptance
Accessibility acceptance
Bilingual acceptance
Migration acceptance
Operational acceptance
Provider acceptance
Training and adoption acceptance
Business-owner acceptance
Executive acceptance
Release authorization
```

## Required acceptance-class content

For every class, register REG-1201 identifies:

```
Evidence required
Decision authority
Reviewer qualification
Independence requirement
Permitted disposition
Conditions permitted
Prohibited inference
Dissent treatment
Outstanding-obligation treatment
Revocation and reconsideration rule
Release effect
```

Every acceptance class identifies the evidence it requires, the authority that
decides it, the independence required of that authority, the conditions and dissent
it may carry, and the effect its disposition has on release.

## Required doctrine

The following separations are fixed and fail closed:

> Technical acceptance is distinct from business acceptance.
> Business acceptance is distinct from operational acceptance.
> Operational acceptance is distinct from executive release authorization.
> Stakeholder support is distinct from accountable approval.
> Executive approval is distinct from evidence substitution.

## Boundary

This chapter records the acceptance and release-authorization model. It accepts
nothing, substitutes for no evidence, and authorizes no release. Every record
carries the fixed non-authorizing posture.
