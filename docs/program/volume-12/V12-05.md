## Purpose

This chapter defines the evidence-intake requirements for every program domain: the
evidence classes each domain requires, its minimum provenance, and its sufficiency
boundaries. It defines intake obligations; it intakes and accepts no evidence.

## Domains

Evidence-intake requirements are defined, and recorded in register REG-1202 as
evidence requirements, for:

- implementation;
- unit and component verification;
- PostgreSQL behavioural verification;
- contract and integration testing;
- end-to-end workflow testing;
- security;
- privacy and records;
- accessibility;
- bilingual semantic equivalence;
- financial controls and reconciliation;
- data integrity;
- migration;
- backup, restore, and recovery;
- continuity;
- observability and incident response;
- provider operations;
- training and competence;
- adoption;
- business acceptance;
- independent assurance.

## Required intake content

For every domain, register REG-1202 defines:

```
Required evidence classes
Minimum provenance
Environment requirement
Configuration requirement
Data requirement
Independence requirement
Acceptance authority
Known evidentiary limitations
Prohibited substitution
Expiry or revalidation dependency
Final dossier destination
```

## Execution-versus-acceptance distinctions

Evidence intake preserves the distinction between an exercise being executed and
its evidence being accepted:

> Test execution is distinct from accepted evidence and from conformance.
> Operational evidence is distinct from operational readiness and from release
> authorization.
> Migration execution is distinct from migration acceptance and from source
> retirement.

## Domain sufficiency boundaries

The following substitution boundaries are fixed and fail closed:

> Automated accessibility scan output is distinct from manual evidence, from keyboard
> evidence, from assistive-technology evidence, and from a conformance
> determination.
> Bilingual string presence is distinct from semantic-equivalence evidence.
> Security testing is distinct from privacy compliance and from legal compliance.
> Provider certification is distinct from end-to-end service assurance.

## Boundary

This chapter records the cross-domain evidence-intake model. It intakes no
evidence, determines no sufficiency, and authorizes no release. Every record
carries the fixed non-authorizing posture.
