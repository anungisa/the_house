## Purpose

This chapter defines the evidence doctrine for the program: the evidence hierarchy,
what each class may and may not claim, its minimum provenance, and the sufficiency
rules that govern acceptance. It defines evidence obligations; it produces,
submits, validates, or accepts no evidence.

## The evidence hierarchy

The following evidence classes are defined and held distinct. Each is recorded in
register REG-1201 as an evidence class with an authoritative requirement, a
permitted claim, a prohibited inference, and an evidentiary limitation:

```
Documentary definition
Implementation evidence
Automated test evidence
Manual test evidence
Independent-review evidence
Migration evidence
Operational exercise evidence
Provider evidence
Business-acceptance evidence
Executive-decision evidence
Release evidence
Production and stabilization evidence
```

## Claim boundaries

For every evidence class, register REG-1201 identifies:

```
Authoritative requirement
Permitted claim
Prohibited inference
Minimum provenance
Required environment
Required configuration
Required data context
Required identity and authority context
Independence requirement
Review authority
Acceptance authority
Expiry or revalidation dependency
```

Every permitted claim is paired with a prohibited-inference boundary, so that no
evidence class can be read to support a claim wider than the one it authoritatively
establishes.

## Evidence lifecycle distinctions

The evidence lifecycle is governed by fixed distinctions. No stage may be inferred
from an earlier stage:

> Evidence requirement is distinct from evidence submitted.
> Evidence submitted is distinct from evidence valid.
> Evidence valid is distinct from evidence sufficient.
> Evidence sufficient is distinct from evidence accepted.

## Sufficiency doctrine

Sufficiency is a separate determination from existence and from validity. The
following rules are fixed:

> Evidence existence is distinct from evidence sufficiency.
> Evidence sufficiency is distinct from evidence acceptance.
> Evidence acceptance for one object is distinct from system-wide conformance.
> Absence of observed failure is distinct from absence of defect.
> A generated projection is distinct from authoritative evidence.
> A provider assertion is distinct from end-to-end institutional proof.

## Boundary

This chapter records an evidence doctrine and claim boundaries. It accepts no
evidence, confers no sufficiency determination, and authorizes no release. Every
record carries the fixed non-authorizing posture: implementation, operations, and
release unauthorized; evidence not available or not accepted; acceptance not taken;
release not authorized.
