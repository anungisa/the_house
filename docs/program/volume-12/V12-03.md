## Purpose

This chapter defines the controlled evidence object: what every future evidence
record must bind, how its integrity and reproducibility are governed, and how
retention, expiry, and revalidation are controlled. It defines the evidence-object
obligation; it records, produces, or accepts no evidence object.

## The controlled evidence object

Every future evidence record must bind the following, as recorded in register
REG-1202 for each evidence object:

```
Evidence identifier
Requirement
Test, procedure, migration stage, or operational obligation
System or service
Component or capability
Version and commit
Configuration
Environment
Identity and authority context
Organization and jurisdiction
Dataset, fixture, migration batch, or operational data context
Provider state
Execution time
Observed result
Evidence location
Integrity mechanism
Executor
Reviewer
Independence level
Defect, exception, or waiver relationship
Acceptance disposition
Retention dependency
Expiry or revalidation date
```

## Integrity, reproducibility, and retention

Every evidence object carries an integrity mechanism, a reproducibility statement,
a retention dependency, and an expiry or revalidation date. Integrity and
reproducibility are governed as distinct properties from location and from
retention.

## Required distinctions

The following distinctions are fixed:

> Evidence location is distinct from evidence integrity.
> A reproducible procedure is distinct from a reproduced result.
> Evidence retained is distinct from evidence still current.
> Evidence copied is distinct from provenance preserved.

## Boundary

This chapter records the evidence-object model. It binds no concrete evidence,
proves no integrity, and accepts nothing. Every record carries the fixed
non-authorizing posture.
