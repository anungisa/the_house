## Purpose

This chapter defines the evidence required to demonstrate that a release candidate
has been formed and qualified, and the boundaries that keep candidate formation
distinct from acceptance and from release authorization. It defines these evidence
obligations; it forms, qualifies, accepts, or authorizes no release candidate.

## Required demonstrations

Evidence requirements, recorded in register REG-1202, are defined to demonstrate:

- implementation completion;
- source and build provenance;
- dependency completeness;
- physical database behaviour;
- resource-aware authorization;
- configuration completeness;
- secret and credential dependencies;
- production composition;
- deployment path;
- rollback readiness;
- release-candidate formation;
- environment qualification.

## Release-candidate contents

For every release candidate, register REG-1202 requires:

```
Contained work packages
Version and commit
Configuration baseline
Environment qualification
Database state
Migration state
Provider state
Required test evidence
Security and privacy evidence
Accessibility and bilingual evidence
Operational evidence
Known defects
Conditions and waivers
Rollback dependency
Acceptance authorities
Release-gate status
```

## Required distinctions

The following distinctions are fixed and fail closed:

> Build succeeded is distinct from deployment path proven.
> Environment provisioned is distinct from environment qualified.
> Implementation complete is distinct from verification complete.
> Release candidate assembled is distinct from release candidate accepted.
> Release candidate accepted is distinct from release authorized.

## Boundary

This chapter records the release-candidate evidence model. It forms no candidate,
qualifies no environment, accepts nothing, and authorizes no release. Every record
carries the fixed non-authorizing posture.
