## Purpose

This chapter defines the implementation-facing evidence that would be required to
accept the club-affiliation vertical: source evidence, build-provenance evidence,
database-behaviour evidence, environment-qualification evidence, configuration
evidence, deployment-path evidence, and release-candidate evidence. Each is recorded
in REG-1202 under its controlled requirement kind. No source is written, no build is
produced, no environment is provisioned, no database is exercised, and no deployment
path is executed by this chapter.

## Implementation and source evidence

Implementation evidence would establish that the governed capabilities named in the
affiliation evidence domain exist as governed source bound to a specific commit and
requirement, reviewed under segregation of duties. The requirement is documentary
only. It records what must be shown, the minimum provenance that would bind the
evidence to a commit, and the acceptance authority that would review it.

The governing distinction is fail-closed: **Implementation completed is not
implementation evidence accepted.** Writing code, and even demonstrating it
informally, is not the same as producing evidence that binds an implementation to a
requirement and having that evidence independently accepted.

## Build-provenance and deployment-path evidence

Build-provenance evidence would establish that a specific release candidate was
produced reproducibly from a specific reviewed commit, with a recorded supply-chain
provenance. Deployment-path evidence would establish that the qualified release
candidate can traverse the governed promotion path to its destination without
unrecorded mutation.

Two fail-closed distinctions govern this area:

- **Source present is not build reproducible.** The existence of reviewed source
  does not establish that a build is reproducible or provenance-bound.
- **Build succeeded is not deployment path proven.** A successful build does not
  establish that the release candidate can be promoted through the governed
  deployment path, nor that promotion preserves integrity.

Release-candidate formation evidence remains distinct from acceptance and from
release authorization: a formed release candidate is a subject of evidence, not an
accepted or released artifact.

## Database-behaviour evidence

Database-behaviour evidence would establish that the persistence layer enforces the
governed invariants of the affiliation vertical — tenant and parent scoping,
uniqueness, versioning, history, and referential integrity — as observable physical
behaviour, not as inspected declarations.

The fail-closed distinctions are explicit: **Schema exists is not database invariant
proven.** A present schema, or an inspected migration, is not proof that the
invariant holds under concurrent physical behaviour. Database behaviour is not schema
inspection is not a mocked result: behavioural evidence must bind to a real physical
database exercise, not to a static reading of a definition and not to a mocked or
stubbed substitute.

## Environment-qualification and configuration evidence

Environment-qualification evidence would establish that the environment in which any
later evidence is produced is itself qualified: provisioned, configured, and
representative of the governed target. Configuration evidence would establish that
the configuration under which the capability operates is complete, governed, and
bound to the evidence produced.

The fail-closed distinction is: **Environment provisioned is not environment
qualified.** The existence of an environment does not establish that it is qualified,
representative, or governed; unqualified environments produce evidence that cannot be
accepted.

## Prohibited inferences

Nothing here asserts that any implementation, build, database, environment,
configuration, deployment path, or release candidate exists, has been produced, or
has been exercised. Implementation, build, database, environment, configuration,
deployment-path, and release-candidate evidence are defined as obligations for a
later, separately authorized package. No evidence is manufactured or accepted, and
no release candidate is accepted or released.
