## 1. Purpose

This chapter consolidates the Package 2 release units into governed implementation
waves and synthesizes a documentary release roadmap. These are planning
constructs, not approved delivery commitments.

## 2. Planning wave decomposition

The indicative wave decomposition (register REG-1002, kind `IMPLEMENTATION_WAVE`)
is:

- Wave 0 — Delivery and environment enablement
- Wave 1 — Organization and representative authority
- Wave 2 — Affiliation draft, applicability, and requirements
- Wave 3 — Evidence, completeness, and submission
- Wave 4 — Review, return, correction, and resubmission
- Wave 5 — Decision, finance, and reconciliation
- Wave 6 — Exactly-once activation, standing, and expiry
- Wave 7 — Migration, coexistence, and operational readiness
- Wave 8 — Release-candidate formation and assurance

## 3. Per-wave definition

For every wave the roadmap records contained work packages, entry conditions, exit
conditions, required environments, required implementation evidence, required test
evidence, security and privacy evidence, accessibility and bilingual evidence,
migration evidence, operational evidence, known limitations, rollback dependency,
acceptance authority, and authorization gate.

## 4. Release-candidate posture

A release candidate is a documentary release unit that has satisfied its planned
evidence obligations on paper only. **A release candidate is not an accepted
release and is not a deployment.** Release-candidate formation is planned; no
release is produced, accepted, deployed, or launched by this package.

Release unit defined is not release candidate accepted is not deployment
authorized.
