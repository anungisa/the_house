## V8-31.1 Purpose

This section is normative.

This chapter opens Package 4 by defining the authority doctrine for the governed bulk and external exchange plane. It states who holds institutional authority over providers, external institutional systems, provincial and territorial systems, internal batch exchanges, file imports and exports, migrations, transitional and manual exchanges, and reporting and analytics feeds. It authorizes no implementation, no provider selection, no transfer mechanism, and no migration activity. It defines contract-governance obligations only.

## V8-31.2 Institutional authority is retained across every exchange

This section is normative.

Institutional authority over governed facts is retained by Curling Canada and is never transferred to a provider, an external system, a file, a batch, or a migration process. An external party may produce information, hold custody of data, or assert a claim, but the authority to determine a governed fact remains internal. Provider custody is a handling relationship, not an authority relationship. Custody of data does not become institutional authority over the meaning of that data.

## V8-31.3 Received is not accepted, imported, or authoritative

This section is normative.

The doctrine preserves the following distinctions and does not collapse them:

```
File received
≠ file accepted
≠ records imported
≠ imported records authoritative

Provider assertion
≠ Curling Canada determination

Migration mapping
≠ identity resolution
≠ authority confirmation

Export generated
≠ disclosure authorized
≠ recipient receipt confirmed
```

Each arrow is a governed boundary. A file may be received without being accepted; records may be imported without becoming authoritative; a provider may assert a value that Curling Canada does not determine to be true; an export may be generated without disclosure being authorized or recipient receipt being confirmed.

## V8-31.4 Every exchange family names its governing attributes

This section is normative.

For every exchange family, the governed record identifies the retained institutional authority, the exchange purpose, the producer, the consumer, the source of truth, the information classification, the authority required, the validation dependency, the acceptance posture, the reconciliation dependency, the records dependency, the provider dependency, and the future gate under which any implementation would be separately governed. An exchange family that cannot name its retained institutional authority and its source of truth fails closed and is not defined.

## V8-31.5 Provider custody does not confer authority

This section is normative.

A provider that stores, transmits, or processes governed data holds custody of that data. Custody imposes handling, incident, continuity, return, deletion, and exit obligations on the provider, but it confers no authority to determine governed facts, to create governed standing, or to bind Curling Canada. A provider assertion is an input to institutional determination, never a substitute for it. This doctrine is applied throughout Package 4.

## V8-31.6 No claim of implementation

This section is normative.

Nothing in this chapter asserts that any provider relationship, exchange, file transfer, import, export, or migration is implemented, contracted, procured, or operational. Every controlled Package 4 record is in a not-implemented-or-not-proven posture. This chapter authorizes documentary definition only.

## V8-31.7 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It selects no provider, no vendor, no format, no transfer mechanism, no storage location, and no migration approach. It defines no executable contract, endpoint, adapter, importer, exporter, or script, and it changes no governed state. Every controlled Package 4 record remains in a not-implemented-or-not-proven posture and authorizes no construction.
