## V3-26.1 Purpose

This section is normative.

This chapter defines how the affiliation service is functionally delivered across the
organizational network (CAP-V3-026, OUT-V3-026, FR-V3-026). It records operating coverage
without inventing business hours, service-level commitments, named employees, permanent
organizational units, or headcount. It authorizes no implementation.

## V3-26.2 Service functions in scope

This section is normative.

The service-delivery model covers the following delivery participants:

- Curling Canada.
- PTSOs and member associations.
- Clubs.
- National and jurisdictional reviewers.
- Finance and reconciliation.
- Policy and compliance.
- Service operations.
- Support.
- Product and technology stewardship.
- External service providers.

## V3-26.3 Service-function record template

This section is normative.

For every service function, the model records:

```
Service function
Primary beneficiary
Accountable function
Performing function
Jurisdictional coverage
Operating trigger
Inputs
Outputs
Required competencies
Dependency
Exception route
Continuity requirement
Validation status
```

## V3-26.4 Delivery classification

This section is normative.

Each service function is classified by its delivery model (BR-V3-026, RULE-V3-021):

```
Nationally centralized
Jurisdictionally distributed
Club-performed
Shared-service
External execution
Manual transitional
Future-state unresolved
```

A delivery classification is a recorded determination, not an informal expectation. Where
the future-state delivery of a function is undecided, it is classified as future-state
unresolved and carries an owner and a future gate rather than an implied arrangement.

## V3-26.5 Coverage constraints

This section is normative.

The service-delivery model does not invent business hours, service-level commitments,
named employees, permanent organizational units, or headcount (BR-V3-026, CTRL-V3-032).
Accountable and performing functions are recorded as functions, not as individuals.
