## V3-28.1 Purpose

This section is normative.

This chapter defines how each business function may be delivered across internal, shared,
club-performed, and external arrangements (CAP-V3-028, OUT-V3-028, FR-V3-028) while
preserving retained Curling Canada authority. It authorizes no implementation.

## V3-28.2 Sourcing classifications

This section is normative.

Each business function is given a sourcing classification (BR-V3-029, RULE-V3-023):

```
INTERNAL_NATIONAL
INTERNAL_JURISDICTIONAL
SHARED_SERVICE
CLUB_PERFORMED
EXTERNAL_PROVIDER
TRANSITIONAL_MANUAL
SOURCING_DECISION_PENDING
```

## V3-28.3 Dependency categories

This section is normative.

Relevant dependency categories include:

- Payment processing.
- Accounting.
- Identity.
- Registration.
- Communications delivery.
- Document and knowledge services.
- Analytics.
- Learning and accreditation.
- Technical operations.
- Privacy, security, accessibility, or bilingual specialist support.

## V3-28.5 Sourcing constraints

This section is normative.

The sourcing model must not (BR-V3-029, NFR-V3-011, CTRL-V3-035):

- Select a vendor.
- Approve procurement.
- Confirm unsupported provider capabilities.
- Transfer governed authority to a provider.

Retained Curling Canada authority is preserved across every sourcing classification, and
no sourcing arrangement silently transfers governed decision authority. Contractual
capability that has not been verified is recorded as a contractual question, not asserted
as fact.

## V3-28.6 Validation status

This section is normative.

The sourcing definitions are author-asserted. Sourcing validation involves Curling Canada
National Operations (STK-V3-001), the affiliation service owner (STK-V3-017), external
service providers (STK-V3-019) at the level of unverified assumptions only, and financial
reconciliation with Hélène for financial dependencies. Pending validation blocks only the
affected sourcing definition.
