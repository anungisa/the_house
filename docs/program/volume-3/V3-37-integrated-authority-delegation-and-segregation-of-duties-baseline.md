## V3-37.1 Purpose

This section is normative.

This chapter consolidates the authority model across all packages into one integrated authority,
delegation, and segregation-of-duties baseline (CAP-V3-037, OUT-V3-037, FR-V3-037). It authorizes
no implementation and confers no new authority.

## V3-37.2 Authority domains

This section is normative.

The baseline demonstrates separation among the following authority domains:

```
Policy definition
Pathway determination
Evidence review
Affiliation decision
Fee-policy authority
Payment execution
Accounting confirmation
Financial reconciliation
Activation authorization
Activation execution
Administrative correction
Governed-decision correction
Support
Operational assurance
Executive material commitment
```

## V3-37.3 Authority-domain record

This section is normative.

For each authority domain the baseline records:

- accountable function;
- permitted delegation;
- prohibited combinations;
- required evidence;
- conflict controls;
- escalation;
- correction authority;
- future validation.

## V3-37.4 Prohibited combinations

This section is normative.

The baseline explicitly prevents (BR-V3-040, RULE-V3-031, CTRL-V3-045):

- support approving affiliation;
- reviewers confirming their own financial reconciliation;
- finance changing affiliation decisions;
- external providers receiving Curling Canada decision authority;
- Button visibility or task access being interpreted as governed authority.

An authority domain is valid only when its prohibited combinations and conflict controls are
recorded, and any prohibited combination blocks the arrangement.

## V3-37.5 Validation status

This section is normative.

The authority baseline is author-asserted. Operating validation involves Curling Canada National
Operations (STK-V3-001) and the risk and assurance function (STK-V3-018). Pending validation
blocks only the affected authority domain.
