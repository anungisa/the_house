## V7-30.1 Purpose

This section is normative.

This chapter defines the affiliation reference prototypes for the club-affiliation experience. It records reference prototypes in register REG-701 as reference candidates that are not approved. A reference prototype is a documentary walkthrough of a governed flow; it is not a production interface, is not usability-validated, and is not stakeholder-approved.

## V7-30.2 Reference prototypes are candidates, not approvals

This section is normative.

Every reference prototype is recorded as a reference candidate that is not approved. A reference prototype may present high-fidelity documentary design intent, but it is never described as stakeholder-approved, usability-validated, production-final, or implemented. Each prototype names the governed flow it walks through and traces to the governed stages it covers.

## V7-30.3 Full affiliation vertical

This section is normative.

The reference prototypes cover the full affiliation vertical: representative authority; organization and club identity; initiation and applicability; requirements and evidence; completeness and submission; review and return; correction and resubmission; decision; finance and reconciliation; activation; and standing and expiry. Each stage of the vertical is represented so that the reference set is coherent end to end.

## V7-30.4 Club-facing and governed staff surfaces

This section is normative.

The reference prototypes represent both the club-facing surfaces and the governed staff surfaces. Club-facing prototypes preserve the authority posture of a representative and never present staff authority. Governed staff prototypes preserve the reviewer, finance, support, privacy, and administrative-correction separation and never merge those authorities.

## V7-30.5 Traceability and governed semantics

This section is normative.

Each reference prototype traces to the interaction model and screen-state matrix of Package 2 and to the component and content specifications of Package 3. Every state presented in a prototype retains its governed semantic source. A prototype never presents a status, decision, or activation that the governed system has not recorded.

## V7-30.6 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It creates no production user interface, production content, validated translation, coded interface, design-system implementation, executable workflow, or interface or integration contract, and no procurement, sequencing, staffing, cost, pilot, rollout, or master development plan. It defines documentary affiliation reference prototypes as reference candidates only, pending Gate V7-G3, and asserts no stakeholder approval, usability validation, production finality, or implementation.
