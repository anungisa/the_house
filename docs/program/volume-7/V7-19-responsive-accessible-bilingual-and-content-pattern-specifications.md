## V7-19.1 Purpose

This section is normative.

This chapter specifies responsive, accessible, bilingual, and content-pattern requirements that apply across the interaction model. It records content requirements, status and error messages, recovery paths, accessibility behaviours, bilingual semantics, and experience patterns in register REG-702.

## V7-19.2 Content and messaging

This section is normative.

Content makes institutional consequences clear at consequential moments and never overstates authority, decision, or activation. Status messages distinguish receipt, review, decision, and activation as distinct meanings. Error messages explain the problem and route to a recovery path without exposing internal implementation detail.

## V7-19.3 Recovery

This section is normative.

Recovery paths preserve entered work after a failed submission, restore draft context after an interrupted session, and route to support-assisted guidance without transferring governed authority to support. Recovery applies across primary, exception, and degraded conditions.

## V7-19.4 Accessibility

This section is normative.

Accessibility requirements apply to every interaction state and recovery path, not only to primary success paths. Every flow and state is operable by keyboard with managed focus, status and error changes are announced to assistive technology, evidence interactions are accessible, and an accommodation path is available where interaction is blocked without weakening governance controls.

## V7-19.5 Bilingual and responsive patterns

This section is normative.

Bilingual content preserves equivalent institutional meaning rather than literal translation, and status terminology is consistent across both languages. Interactions remain usable across responsive and low-bandwidth conditions without hiding institutional obligations. Consequential confirmations, evidence provenance, stale-disclosure, and interruption handling are specified as reusable experience patterns.

## V7-19.6 Explicit non-authorizations

This section is normative.

This chapter does not authorize production user interface, executable workflows, interface or integration contracts, final visual design, branded mockups, design tokens, production content, translations, procurement, staffing, cost commitments, pilots, rollout, or a master plan. It defines documentary interaction behaviour only, pending Gate V7-G2.
