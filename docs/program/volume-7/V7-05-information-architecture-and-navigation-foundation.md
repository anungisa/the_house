## V7-05.1 Purpose

This section is normative.

This chapter defines the experience-level information architecture for the club-affiliation experience. Each area is recorded in register REG-702 with its purpose, primary actor, authoritative source, permitted actions, status semantics, deep-work destination, access condition, privacy posture, accessibility dependency, and bilingual dependency. This chapter creates no coded navigation and no final screen layout.

## V7-05.2 Areas

This section is normative.

The information architecture defines the following areas: club home, affiliation, membership, compliance, applications, support, services, documents, organization profile, and notifications and required actions. Each area names an authoritative source and an access condition.

## V7-05.3 Authoritative source and access condition

This section is normative.

Every area names an authoritative source from which its presented information is derived and an access condition that governs who may reach it. An area never becomes an independent source of truth; it presents governed information from its authoritative source.

## V7-05.4 Deep-work destinations and status semantics

This section is normative.

Each area names a deep-work destination for the tasks it introduces, and it names the status semantics it presents. Status semantics present governed state without deciding it.

## V7-05.5 Privacy, accessibility, and bilingual dependencies

This section is normative.

Each area names its privacy posture, its accessibility dependency, and its bilingual dependency. Areas that present sensitive information carry stronger privacy postures and disclose the minimum necessary information.

## V7-05.6 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It creates no coded navigation, final screen layout, final visual design, production content, coded interface, design-system implementation, or executable workflow, and no procurement, sequencing, staffing, cost, pilot, rollout, or master development plan. Every controlled record remains in a not-implemented-or-not-proven posture.
