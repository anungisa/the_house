## V7-23.1 Purpose

This section is normative.

This chapter defines the component taxonomy for the club-affiliation experience. Each component is specified by anatomy, variants, states, permitted and prohibited uses, accessibility, bilingual expansion, privacy posture, and traceability to a governed semantic source. Components are recorded in register REG-701 as documentary component specifications.

## V7-23.2 Component families

This section is normative.

The taxonomy covers the component families required by the affiliation experience: navigation, page headers, cards, task items, progress, forms, validation, status, timelines, tables, responsive lists, evidence, documents, confirmations, notifications, and help and support. Each family is specified once as a reusable pattern and reused across surfaces so that meaning and behaviour remain consistent.

## V7-23.3 Anatomy and variants

This section is normative.

Each component names its anatomy, the parts that compose it, and its variants, the permitted forms it takes across contexts. Variants exist only to serve governed differences in meaning or task, never to introduce decorative divergence. A component variant never changes the governed meaning of the information it presents.

## V7-23.4 States

This section is normative.

Each component specifies its complete set of states, including default, focus, loading, empty, success, error, denied, stale, and disabled conditions as applicable. Every state names the governed semantic source that determines it. No component presents a success, approval, or activation state that the governed system has not recorded.

## V7-23.5 Permitted and prohibited uses

This section is normative.

Each component names its permitted uses and its prohibited uses. Prohibited uses prevent a component from overstating authority, implying a decision, presenting stale information as authoritative, or bypassing a required confirmation or evidence step. Accessibility and bilingual expansion are specified for every component so that meaning is preserved for assistive technology and in both official languages.

## V7-23.6 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It creates no production content, coded interface, design-system implementation, design tokens, stylesheet, framework configuration, or executable workflow, and no procurement, sequencing, staffing, cost, pilot, rollout, or master development plan. It defines a documentary component taxonomy only, pending Gate V7-G3.
