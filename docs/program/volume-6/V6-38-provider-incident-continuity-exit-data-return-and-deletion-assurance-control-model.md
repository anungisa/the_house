## V6-38.1 Purpose and scope

This section is normative.

This chapter defines the control model for provider incidents, provider continuity,
provider exit, data return, and deletion assurance for the affiliation service. It builds
on the service-trust model of Package 2 and defines the obligations that must exist before
reliance on any external provider. It defines a control model only. It selects no provider,
signs no contract, and authorizes no implementation.

## V6-38.2 Accountability is retained across providers

This section is normative.

Entrusting governed data or capability to an external provider does not transfer
institutional accountability. Each provider incident context records an
institutional-authority-retained statement so that the accountable authority for governed
data and outcomes remains The House regardless of provider arrangements. No provider
relationship is established by this chapter.

## V6-38.3 Provider incidents and continuity

This section is normative.

A provider may suffer an incident or become unavailable. Each provider context records a
provider responsibility, an incident-notification dependency so that provider incidents are
surfaced under governed incident obligations, and a continuity dependency and substitution
dependency describing that continuity of governed service must not depend on a single
unrecoverable provider. No provider continuity capability is operated here.

## V6-38.4 Provider exit and data return

This section is normative.

Reliance on a provider must be exitable. Each provider context records an exit trigger and a
data-return requirement so that governed data can be returned to institutional control on
exit, in a usable form and with integrity. A provider relationship without a defined exit and
data return is prohibited by the model. No exit is performed here.

## V6-38.5 Deletion assurance and residual copies

This section is normative.

On exit, governed data held by a provider must be deleted under assurance. Each provider
context records a deletion-evidence requirement and a residual-copy posture so that residual
or backup copies held by the provider are accounted for and disposed of under evidence.
Provider assertion of deletion without evidence is not deletion assurance. No deletion is
performed or assured here.

## V6-38.6 Provider certification is not service assurance

This section is normative.

A provider certification or attestation is evidence about the provider, not proof that the
governed service is assured. Each provider context records a contract-validation status and
an independent-assurance dependency so that reliance on a provider requires validated
contractual and assurance evidence owned by the accountable authority. No provider assurance
is asserted by this chapter.

## V6-38.7 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It selects, engages, or approves no provider,
negotiates or signs no contract, moves, returns, or deletes no data, and configures no
provider integration. It makes no claim that any provider is assured, continuous, or exitable.
Every record introduced by this chapter remains `authorizes_implementation: false` and
`implementation_status: NOT_IMPLEMENTED_OR_NOT_PROVEN`.
