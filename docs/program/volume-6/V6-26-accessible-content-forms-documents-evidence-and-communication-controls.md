## V6-26.1 Purpose and scope

This section is normative.

This chapter defines accessibility controls for the content assets of the
affiliation service: forms, documents, evidence-facing content, and communications.
It defines the required accessible-alternative and verification structure only. It
authors no content, produces no document, sends no communication, and authorizes no
implementation.

## V6-26.2 Content-asset classes

This section is normative.

The accessibility content model recognizes classes of content asset: interactive
forms a user must complete; documents a user must read or submit; evidence-facing
content a user must review; and communications a user must receive. Each accessible
content control records the content asset it governs and the required accessible
behaviour. The class model organizes controls; it creates no content.

## V6-26.3 Accessible alternatives

This section is normative.

Where content cannot be made directly perceivable to every user, an equivalent
alternative representation must be available so that the user reaches the same
governed understanding. Each control records the alternative-representation
requirement and any document-accessibility dependency on a producing authority or
provider. Recording the requirement produces no alternative and authors no content.

## V6-26.4 Documents and provider dependencies

This section is normative.

Where a document or communication is produced by an external provider, the
accessibility of that artifact carries a recorded provider dependency that must be
validated before reliance. A provider dependency does not select a provider and does
not accept provider assurance as conformance; provider assurance remains distinct
from validated accessibility conformance.

## V6-26.5 Verification of content accessibility

This section is normative.

Every accessible-content control records a verification method so that the
accessibility of the content asset can be independently validated. No content
accessibility is claimed on the strength of this chapter, and no content is deemed
conformant without recorded verification evidence produced under a future gate.

## V6-26.6 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It authors no content, produces no form or
document, sends no communication, selects no provider, and claims no accessibility
conformance. Every record introduced by this chapter remains
`authorizes_implementation: false` and `implementation_status:
NOT_IMPLEMENTED_OR_NOT_PROVEN`.
