## V6-28.1 Purpose and scope

This section is normative.

This chapter defines the inclusive-service control model for the affiliation service:
the accommodation controls that preserve equivalent outcomes for users who cannot use
the default path, the support roles that assist users, and the exception paths that
are part of the governed service rather than informal workarounds. It defines controls
only. It grants no accommodation, assigns no support role, and authorizes no
implementation.

## V6-28.2 Accommodation preserves equivalent outcomes

This section is normative.

Where a user faces a barrier to the default service path, an accommodation must
preserve an equivalent governed outcome. Each accommodation control records the user
barrier it addresses, the permitted accommodation, and the equivalent-outcome
requirement it must satisfy. An accommodation changes the path, not the governed
outcome; it never lowers the outcome or bypasses a governed control.

## V6-28.3 Support roles

This section is normative.

Support roles that assist users are governed: the control records the support role, the
minimum-necessary information it may rely upon, and the prohibited inference it must not
draw. Support operates under minimum-necessary information and preserves the user's
rights. Recording a support role assigns no role and grants no access.

## V6-28.4 Exception paths are part of the service

This section is normative.

An exception path — an alternative route to complete a governed workflow — is a
governed part of the service, not an informal workaround. Exception paths carry the
same governed outcome, the same evidence expectations, and the same authority
structure as the default path. Informal workarounds outside the governed model are
prohibited. This chapter defines the requirement for governed exception paths; it
builds none.

## V6-28.5 Accommodation privacy

This section is normative.

Accommodation and support must protect the privacy of the user requesting them:
information about a user's barrier or accommodation is minimum-necessary, is not used
for any purpose beyond providing the accommodation, and supports no prohibited
inference about the user. This control records the privacy constraint; it processes
no personal data and makes no determination about any user.

## V6-28.6 Explicit non-authorizations

This section is normative.

This chapter authorizes no implementation. It grants no accommodation, assigns no
support role, builds no exception path, processes no personal data, and makes no
determination about any user. Every record introduced by this chapter remains
`authorizes_implementation: false` and `implementation_status:
NOT_IMPLEMENTED_OR_NOT_PROVEN`.
